# Coverage: /zen/zen6-max (components/pages/model/ZenMax.jsx, ZenMax.css)

- **2.1 Strategy and conversion:** Persona/Goal/CTA in the file header (enterprise buyer, `contact_sales_submit`). One solid ask, "Talk to sales", in the hero and at the close; "Run it on your own GPUs" is a text link with an arrow. Gap: no `lib/cta.js` exists yet, so the labels are inline (Hanzo's own words) and there is no `data-cta`.
- **2.2 Information architecture and navigation:** I removed the breadcrumb-style "Zen" link above the h1 (no eyebrow over a headline); /zen stays reachable from the header menu. The shared header, footer and ⌘K are untouched. Gap: no visible breadcrumb.
- **2.3 First impression and page narrative:** The first screen sells on its own: the h1 cuts in on load and Hanzo's lede and "Talk to sales" sit over the playing Zen film (white on the film, ink once it has settled into its card). The page then goes one idea per screen: promises, the pinned rack chapters, the B300/B200 sheet, and a close with one ask.
- **2.4 Conversion system:** One solid button per screen through the kit `<Cta>`, with `data-cta` set to `zen6max.hero`, `zen6max.hero.gpus` and `zen6max.close`. The hero ask carries `thumb`, so the shared ask bar shows "Talk to sales" after the hero. At 375×812 the ask bar never covers a page button; at 1470×801 controls only pass under it while scrolling.
- **2.5 Trust and proof:** Every figure is Hanzo's copy (9,216 GB, 5,760 GB, 8 x 288 GB, 2,304 GB, 1,440 GB, 8 x 3.84 TB, 31 TB), and each server column keeps its NVIDIA user-guide source link. No badges, seals or new claims. The "3.7 trillion parameters" meta line is not shown on the page, because the live body does not show it.
- **2.6 Content presentation (copy untouched):** Parity 46/46 text and 4/4 links. Type is 13px or more on desktop (the server labels were raised from 12px) and 14px or more on phone. The specs are a `role=table` sheet, and "Around the servers" is a drawer that stays in the HTML.
- **2.7 Visual design system:** No UI hues, only greys, silvers, black and white; colour comes only from the Zen film. Radii are 28px for hero objects and the panel and 16/12px inside. No `app/tokens.css` (CANON) exists yet, so the values are local.
- **2.8 UI component library:** The asks use the kit `<Cta>`. The server switch is a `role=radiogroup` with arrow keys, the planning buttons and sheet columns use `aria-pressed`, and the drawer uses `aria-expanded`. Every control presses to .98, and hovers sit behind `@media (hover: hover)`.
- **2.9 Motion and interaction:** The signature is the pinned rack chapters (state stepped by IntersectionObserver). Supporting motion is the Stage settle (scroll), the count-up, magnetic asks and the Sigil; the film plays on its own. Scroll is 2 of about 7 motions, and `variety.py` reports 4 techniques with 0 fade-ups. Reduced motion shows the settled stage, an unpinned page and instant states.
- **2.10 Media:** The Zen film plays through the kit `<Film>` (`/models/zen.webm`, 248 KB, with a poster). It plays only while on screen and never under reduced motion or Data Saver, and it has a 44px pause and play control (named Pause or Play).
- **2.11 Mobile and responsive:** At 375×812 there is no sideways scroll, the stage is unpinned with the film card below the copy, and tap targets are 44px or more. Gap: the rack panel stays sticky on phones (about 380px tall) while its chapters pass below it, which goes against plan item "no big sticky at ≤900".
- **2.12 Accessibility (WCAG 2.2 AA):** One h1, real buttons, keyboard on every control and visible focus. The film and the Sigil are `aria-hidden`. Gap: no axe or VoiceOver run; while it scrolls, the h1 uses `mix-blend-mode: difference` over the film (it ends black on white).
- **2.13 Performance and engineering:** The Stage moves through one CSS variable that sets transform only. There is one Sigil and the film is IO-paused. The count and the rack animate only in view. Not measured: LCP, CLS and INP; no Lighthouse run.
- **2.14 SEO and machine files:** Title, description and JSON-LD come unchanged from `app/zen/zen6-max/page.jsx` and `content/pages.json`. All text is in the server HTML, including the closed drawer and the B200 column.
- **2.15 Catalogue and product pages:** A model page: `data-morph-target` on the h1 so a card can open into it, and the B300/B200 spec sheet. There is no price or context row because Hanzo's page lists none.
- **2.16 Developer experience:** Does not apply: no code, install command or API sample on this page.
- **2.17 States and resilience:** With JS off, a `<noscript>` style settles the stage and shows the film's poster (no native video frame), plus the rack servers, all four chapter steps and the open drawer. The shared rule clears the inline entrance states. I checked this with a Playwright `javaScriptEnabled:false` run at 1470×801 and 375×812: the h1, lede and asks are visible. Gap: no error boundary around the Sigil.
- **2.18 Measurement and handover:** The `<Cta>` buttons send `cta_click` with their `data-cta` ids; no other events are wired. Proof is in `docs/gallery/zen/zen6-max/` (desktop film and three phone stills); checks were 200, parity 0, `variety.py` OK and `taste.py` OK.
