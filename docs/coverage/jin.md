# /jin coverage (PLAN-COMPONENTS areas 2.1–2.18)

Page file: `components/pages/apps/Jin.jsx` (+ `Jin.css`) · gallery: `docs/gallery/jin/`

1. **Strategy and conversion.** Persona: an ML researcher or engineer curious about self-supervised vision. Goal: see the saccade idea work, then open the docs. One ask, Hanzo's "Read the docs" (docs.hanzo.ai): solid under the title, in the site's sticky ask bar after the hero (every width) and as the one solid button of the close. "View on GitHub" and "Deploy to Cloud" are text links.
2. **Information architecture and navigation.** Hanzo's header and footer are unchanged. Order follows a paper: title and Figure 1, the abstract, the six numbered sections of "What is in the repository" under a sticky running head (section name and 01 / 06), the dark plate where you make the saccade, then the close.
3. **First impression and page narrative.** Nothing sits above the h1: title, byline (Jin, hanzoai/jin), the ask, and Figure 1 beside it on desktop (all of it inside 1470×801) and under it on phones (the input and embedding panes inside the first 660px at 375×812). Figure 1 moves within a second with no input. The abstract follows the object.
4. **Conversion system.** `data-thumb="Read the docs"` and `data-cta="primary"` on the hero ask and on the close ask; `data-ask-name="Jin"` on `<main>` names the page in the site's sticky ask bar, which carries the same label at every width and steps aside while either data-thumb button is on screen, so one solid button shows per screen.
5. **Trust and proof.** Every claim is Hanzo's own sentence. Figures are drawn diagrams of the mechanisms the copy names (context and target encoders, the round trip, Huber/cycle/VICReg, masked patches, UMAP, edge hardware); they carry letters, and the legend under each uses Hanzo's words. No invented numbers.
6. **Content presentation (copy untouched).** Parity 37/37 text and 3/3 links. Detail you open: Table 1 and the agent prompt live in a sheet ("See Table 1"). No kicker or eyebrow above any headline; labels sit beside or under.
7. **Visual design system.** Biz grammar (Display 96, Headline, Body, Zen Mono labels), ink, greys and white only: no hues. Highlights are inverted ink chips (letters, the phase, "predicted"), weight and stroke width. One dark room: the "Make the saccade yourself" plate.
8. **UI component library.** Kit: `A`, `More`, `BizLines`, `BizSheet`, `Paste`. Custom controls (pause, draggable image, close rows) all have hover, press (.98) and focus states; no browser-default controls.
9. **Motion and interaction.** Idle: Figure 1 runs its saccade (shift, predict, shift back, land) while seen, with a 44px Pause/Play. Pointer: drag the image with springs (arrow keys too); the prediction follows on a spring and the losses answer. State: the sheet rises, phase ticks advance. Arrival/scroll: headlines cut into their line; the running head tracks the section. Motion tokens from `lib/motion` (SPRING.sheet).
10. **Media.** Hanzo's own `zen.webp` model image is the input in both instruments, cut into a 4×4 patch grid. Six drawn SVG figures. No video.
11. **Mobile and responsive.** At 375px: title, byline, ask, then Figure 1 (two panes side by side, losses under). Sections stack numeral, text, figure; the running head keeps the section name and count. No text under 14px, every target 44px or more (text links included), no sideways scroll.
12. **Accessibility.** One h1, real buttons and links, `aria-pressed` on Pause, the draggable image is focusable with arrow keys and an aria-label, `aria-live` on the drag state, the sheet traps focus and returns it. Reduced motion: Figure 1 shows the predicted state still; transitions off.
13. **Performance and engineering.** Transform and opacity only; Figure 1's timers run only while it is on screen and not paused; the drag reads motion values and throttles state to 25 fps. No blur, canvas or video. Server HTML has no hidden hero text (JS off is legible).
14. **SEO and machine files.** Metadata and JSON-LD unchanged (`app/jin/page.jsx`). All copy, including the sheet's Table 1 and the prompt, is in the server HTML.
15. **Catalogue and product pages.** Does not apply: Jin is a research page.
16. **Developer experience.** The agent prompt (Paste and ship, with Copy) and Table 1 of the repository sit in the sheet; GitHub and docs links are kept.
17. **States and resilience.** Figure 1 has paused, playing and reduced-motion states; the drag has rest, shifting, shifting back and landed states, each named in the status line. No network data, so no loading or error state.
18. **Measurement and handover.** `data-cta="primary"` marks both asks; no analytics wired yet (pending Hanzo's event log). Filmed with the review film script at 1470 and 375 (`desktop.mp4`, `desktop-hero.jpg`, `phone-1..3.jpg`); interactions checked by script (pause holds, drag lands, the sticky bar steps aside at the close, sheet opens).
