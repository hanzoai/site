## What works
- The hero sells straight away. "Hanzo Crawl" h1 (52px) on the left, lede + one solid "Read the docs" + text "GitHub →" on the right, and the URL→Markdown demo below it. The demo writes `# API` into the black Markdown pane by about 1.5s without any input. It has a pause button, and the `/docs/api · /blog/launch · /pricing/faq` tabs swap both the URL bar and the output (checked on /blog/launch).
- Signature scene: a pinned, scroll-driven stage where the 01–06 list advances and the right panel changes each time (page wireframe → extraction box → fetch/headless split → site tree → 302 refused at the hop → HTTP/MCP). It is one thing in, one thing out, and it is about this product rather than a generic one. Clicking an item also jumps the stage. On phone it becomes a pause button plus 01–06 tabs.
- Pricing "Beyond": a custom slider (`role=slider`, keyboard works; ArrowRight goes to 500,000 and the aria-valuetext updates) that says which plan covers your volume. The selected plan card takes the ink outline.
- Every control I touched answers. Primary hover goes #0a0a0a→#2c2c2e and press is scale(0.98). Related rows fill on hover and nudge their arrow. Copy turns into a drawn tick with "Copied" (aria-label too), and the clipboard holds exactly the displayed prompt.
- No hue anywhere outside the dev overlay. Only one black room (Get Crawl). CLS is 0.0003. No horizontal scroll at 375 (scrollWidth 375). Under reduced motion the Markdown is fully present and every animation has finished by 3.5s.
- Copy parity is clean (108/108, 14/14).

## Fix list (to reach 8+), most important first
1. **Site-tree diagram overlap (desktop and phone).** Re-space the third row of the tree in the scene panel (steps 04–06) so `/docs/api/auth` and `/docs/api/errors` have at least 12px between pills at 1470 (they overlap 19px now). On phone, either move `/api` / `/launch` apart or drop the second-level labels to dots the way the third level already is.
2. **Console error / red badge.** The footer hydration mismatch (`FooterHTML` `__html` differs server vs client) fires on load. It is shared chrome, so file `docs/requests/crawl.md` and get it fixed. The page can't pass with a red badge.
3. **Phone header ask.** At 375 the header stays a solid "Try Hanzo" next to a solid hero "Read the docs". Swap it to the page's ask label and go quiet while the hero ask is on screen, the same as desktop already does. Then there's one solid fill and one label.
4. **"How it works" is a document.** Give the three steps an object that moves: for example, step rows that light a stage of the same URL→Markdown machine from the hero (fetch, extract box, render pane) as each row is reached, or as the row is hovered or focused. Copy stays as it is. Give "Two ways / Reads / Returns" something to look at too, or let the JS/Parallel/LLM/MD figures settle in once rather than sitting as four static giants.
5. **"Send it a URL" console script.** The panel plays "deploy the gateway to staging / reading the project", which has nothing to do with Crawl. Script it from this page's own content (a `/v1/crawl` call returning Markdown), or use a static final frame.
6. **Pricing section top void.** At 1470 the section opens with about 250px of empty white above "Pricing" (d10) because the left column bottom-aligns to the slider card. Tighten the top padding, or start the slider card higher, so the screen doesn't open empty.
7. **Cookie card covers the hero demo** on first load at both sizes (about 215px tall at 375, over the demo). It's shared, but it kills the first 5 seconds. Request a smaller card, or have it wait until after first scroll.
