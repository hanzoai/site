First complaint: "It's the same little stack of tiles three times: the hero, the black bit and again at the bottom. On my phone it's six of the same diagram in a row. Once I've seen it nothing new comes in, and after the black section the page just goes quiet. Where's the moment?"

## The 11 answers
1. **Sells in 5 s, moves within 1 s: yes.** "Hanzo HSM", the lede and View on GitHub sit on the left. On the right an isometric module stack runs a small demo by itself within 1 s: "a key id and some bytes" flies in, "a signature ✓" flies out and the caption cycles "One interface → AWS KMS / Google Cloud KMS / Azure Key Vault". There is a pause control. The weak point is the left side: a 52px two-word h1 in a lot of white, with nothing small or medium around it.
2. **One in, one out: half.** On desktop the black room is a real pinned stage. The stack stays put while the six chapters scroll past, and one layer lights up per chapter with its own callout (a handle / the key, the private key, the password, ML-DSA-65, three shares, the module). The next chapter waits in grey. That part works. After it, "Paste and ship" is one code line in a white field and "Get HSM" repeats the stack a third time, so the second half reads like a document. On phone the pin stacks into six copies of the same diagram plus text, and the page is about 9,500px tall.
3. **A real object in every section: technically yes, but always the same one.** It is the layered-tile stack in the hero, the stage and the band. The agent-prompt code block is the only other object. No other visual (logo wall, figure, module marks) varies the stage.
4. **One ask, nothing floating: mostly, but not clean.** View on GitHub is solid in the hero and the band, and the header takes over the label once the hero ask leaves view on desktop. In the band, though, the "hanzoai" GitHub pill sits right beside View on GitHub with the same href and a different label (MASTER part 4 says adjacent buttons never share an href). The same href shows four or five times. A sticky "WHAT IT IS" label hangs at the bottom centre of the black room through all six chapters, cut off from any heading, and on phone it disappears. The hero pause button floats alone in the top-right corner, far from the object. Scale: one 52px h1, then 32px chapter heads six times in an identical layout and a 44px band head. Nothing grows or shrinks; the rhythm is flat.
5. **Hover and press: mostly yes.** Hovering a module pill selects it, glides the white fill and relabels the stage (a real hover preview). Press is scale(.97). Copy turns to "✓ Copied". The primary darkens to #262626 on hover, which is a colour change with no detail. "Deploy to Cloud" shows no hover change at all. After you press pause, the play glyph is a light icon on a grey disc and almost invisible. On phone, tapping a module pill changes a diagram that has already scrolled off screen above, so the tap answers only the pill.
6. **Overlap, font swap, layout shift: small ones.** CLS is 0.0005 and there is no font swap; the h1 box holds. The hero caption re-centres every time the module name changes, so "One interface →" jumps sideways about 40px per cycle (931 to 892px), a visible twitch. On phone the hero callout pills sit loose above and below the stack: "a key id and some bytes" sits beside the pause button over empty space, and "a signature ✓" ends up just under the header after a scroll. The page has no horizontal overflow at 375 or 320. At 320 the header's Try Hanzo is clipped (shared chrome, not counted).
7. **Reference: apple.com product page.** The pinned stage where one panel changes is genuinely there on desktop. There is no synchronized/osply-style pointer detail and no count-up. The Apple "huge type" moment is missing: the type never becomes the hero.
8. **Different from its neighbours: not verified page by page.** The isometric layered stack in black and white is distinctive for HSM. But using it three times on one page makes the page samey from the inside.
9. **The 18 parts: largely present.** One h1, a pause control first, Reduced motion final state (the demo lands with both callouts shown and `getAnimations()` empty), Copy with a status, a pinned scene stacked under 900px and a closing Band. Gaps: the duplicate GitHub links in the band, a pause control that stays visible under reduced motion with nothing to pause, and empty black space under the module pills on phone (about 250px).
10. **Banned tells: none outright.** No hue (the only colour is the deck greys), no gradient text, no Inter (Zen and Zen Mono load) and no eyebrow above a headline ("GET STARTED WITH HSM" is set below "Get HSM" as a caption, which is allowed). The floating sticky "WHAT IT IS" is close to "something floating over content".
11. **Copy: untouched, but said twice.** Every visible word traces to content/pages/hsm.html or ui-strings (Copied, Pause). But every diagram callout is a fragment of the sentence printed right beside it ("a key id and some bytes", "decrypts it at boot", "no share is ever assembled", "Shares are attested"), so the words appear twice per screen. "One interface → AWS KMS" and "a signature ✓" are compositions with an added arrow or tick, not lines Hanzo wrote. The module names show three times in chapter 06: in the body, the pills and the callout.

Not counted: no console errors, a Next badge with 0 issues and no hydration diff, including on the reduced-motion load. The only console warning is motion.dev's reduced-motion notice. The cookie card was dismissed before judging.

## Fixes, in order
1. **Give the second half its own moment and stop repeating the stack.** Drop the stack from the "Get HSM" band. Close instead on something new from the page's own facts, such as the five module names as a quiet type row that the agent-prompt line resolves into, or the band alone with a 64px+ type moment. "Paste and ship" should be a stage of its own (the prompt typing in once at 60% visible, with the Copy state as the payoff), not one line in a white field.
2. **Phone: one stage, not six.** Under 900px, keep one sticky diagram at the top of the black room (about 45svh), with the chapter text scrolling under it and the stage switching per chapter, as on desktop. Or show the stack once and give each chapter only its lit layer as a small crop. In chapter 06, a pill tap must show its answer in view: put the stage directly above the pills on phone.
3. **Fix the adjacent same-href pair in the band.** Make "hanzoai" a caption-level text link (the `License:` / `hanzoai` meta row), not a button-sized pill next to View on GitHub, or merge them.
4. **Stop the hero caption jumping.** Left-align "One interface →" and give the module name a fixed `min-width` in `ch` (the longest, "Google Cloud KMS"), so only the name crossfades.
5. **Anchor the floating bits.** Move "WHAT IT IS" out of the sticky bottom-centre position: put it under the first chapter heading as a caption, or as the stage's corner caption beside `01 / 06`, and show it on phone too. Dock the pause button to the hero object's bottom-right corner instead of the page corner. Hide it under reduced motion.
6. **Phone hero composition.** Pin the two callout pills to the stack's left and right edges (inside its box) so they never land over empty space or under the header. The stack should sit at true size, centred, with 80px+ in the first 660px.
7. **Stop saying it twice.** Either shorten the callouts to the noun the copy already names (handle, key, password, ML-DSA-65, shares, module) or remove the callout on screens where the body sentence is in view. Drop the added "✓".
8. **Give scale some rhythm.** Let the lit layer or the chapter number grow while it is the moment (for example the `0N / 06` caption scaling to 64px Air, then settling back) so the six chapters are not six identical 32px blocks.
9. **Hover details.** Fix the paused-state play glyph contrast (ink on white, as in the playing state), give "Deploy to Cloud" a hover (underline draw or arrow nudge), and make the primary's hover tell something beyond a darker fill.
10. **Phone black-room tail.** Remove the roughly 250px of dead black under the module pills.
