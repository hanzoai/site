## The 11 questions

**1. Does the first screen sell in 5 s, and does something move within 1 s?** Partly. The ring of 19 satellites around the black "19 / api.hanzo.ai/v1" disc is turning from the first frame (0 ms), so something moves at once. But for the first ~750 ms the hero has a lede and a black ask with no headline above them. The h1 is missing at 0, 250 and 500 ms and is still cutting in at 1 s, so the first impression is a half-built hero. The same happens under reduced motion: the h1 is still absent at 300 ms. Once settled (about 1.2 s) it sells clearly: "Works with everything", the base URL, Get an API key.

**2. One thing in, one thing out, or a document?** Mostly a document. Hero, code block, then a 1,864 px wall of 19 tiles, then the black "Paste and ship" room, then the footer. The best scroll moment is the black room, which starts as an inset rounded card and opens to full width as it is reached. The sticky "INTEGRATIONS · 19" sub-bar with its dotted progress ring is a nice touch. The grid itself just scrolls past. There are about 250 px of dead white between the code block and the catalogue and again before the black room.

**3. Does every section hold a real visual object?** Hero: yes (the ring). Start: yes (the dark code block, with tabs that cycle on their own and a pause button). Paste: yes (the agent-prompt console). Catalogue: no. Nineteen identical #f5f5f5 tiles, each with a white square holding a two-letter monogram ("Cu", "Co", "Ds", "Ha", "Ll") and no real mark, image or preview. Monograms read as placeholders, and "Cu" and "Co" are cryptic. The ring repeats the same monograms, so the page shows the same grey chip 38 times.

**4. One ask in the sticky header, nothing floating, scale rhythm?** The header ask is good. "Try Hanzo" turns into the outlined secondary at the hero, and the header becomes "Get an API key" once past it, the same label as the hero and band (`data-cta` integrations.hero and .band). For about 600 ms on desktop, and for the whole first screen on phone, two solid black fills show together ("Try Hanzo" and "Get an API key"). Nothing floats over content apart from the consent card, which is fine. Scale has some rhythm: a 52 px h1, the large "19" and 26 px section heads, and the OpenAI tile spans two columns. The grid below it is one uniform size for 18 tiles, though.

**5. Does every hover and press answer, with no jumps?** No: there is a layout jump. Hovering a card un-clamps its description, so the whole row grows 269 to 326 px and every row below shifts 57 px (measured). That is the defect James names outright. Other controls answer well: the hero ask lifts 1 px and lightens on hover, presses to scale 0.97, and does not fade. Ring chip hover swaps the disc centre to the name and category ("OpenAI Python SDK / AI SDKs"), which is a real "hover tells you something". But the hovered chip turns solid black and its label vanishes (black on black). The card press tilts and scales to 0.97. Filter tabs show live counts and go grey at 0. Copy puts the exact displayed text on the clipboard, but the button still reads "Copy" 200 ms later, so there is no visible confirmation.

**6. Overlaps, font swap or layout shift?** CLS is 0.0004 on desktop and 0 on phone, with no font swap seen and no horizontal page scroll at 375 or 320 (the body is 348 px wide at 320 but clipped). Nothing in the header overlaps content. The defects are the hover jump in Q5 and a console error: "A tree hydrated but some attributes of the server rendered HTML didn't match" fired on 3 of 5 loads (the desktop and phone walks and the reduced-motion load) and shows the red "1 Issue" badge. Two networkidle loads were clean. It is intermittent, but it fails DONE item 3.

**7. Which reference does it feel like, and is its motion there?** The ring aims at a motion.dev-style orbit and works. The catalogue signature is meant to be synchronized.studio: a card opens into its page and the next hero is the card you clicked. It is not there. On click the card disappears, its monogram grows to about 90 px in a fixed bottom-left spot on an otherwise blank white page for about 1.3 to 1.8 s, then the destination hero cuts in. The destination ("Use Hanzo AI with LlamaIndex" plus a code panel) contains no monogram and no card shape, so nothing carries over. It reads as a loading screen, not a morph. The destination h1 also reads twice in `textContent` ("Use Hanzo AI with LlamaIndexUse Hanzo AI with LlamaIndex"), so check the accessible name.

## Fixes
1. **Kill the hover layout jump.** Card height must not change on hover: overlay the full description inside the fixed card box, or keep the clamp and show the extra detail elsewhere. Pass: every card's top and height are identical before and after hover (0 px delta).
2. **Make the card actually open into its page.** Morph the clicked card's box, with its monogram and title, into the destination hero in 600 ms in-out, with no blank frame. The destination hero must contain the element it came from (title within 12 px). Pass: no frame after click shows an empty white page; on a second visit the destination h1 is visible within 700 ms.
3. **Fix the hydration mismatch.** Pass: 0 console errors and no "Issue" badge on 10 consecutive fresh loads at both sizes, with both `domcontentloaded` and `networkidle`.
4. **Give the catalogue real visuals and break the grey wall.** Use each tool's own mark, or one real per-tool object such as its one-line Hanzo snippet. Vary tile scale beyond the single featured tile, and move the per-tile sentence into the hover or open state so the rest view is name plus category. Pass: no tile shows a two-letter placeholder, and no 1470x801 viewport shows more than 4 explaining sentences.
5. **Render the h1 in the first frame.** The cut-in may animate, but the h1 must be legible at 0 ms (or animate from a visible start) and appear before or with the lede, never after it. Under reduced motion it is in its final state at first paint. Pass: the h1 is visible in the 0 ms and 250 ms frames.
6. **Replace the default search clear button** with a kit-styled, monochrome control, and add the empty-state action ("clear search" from existing UI strings). Searching should cover all categories or show the match count per tab. Pass: no `::-webkit-search-cancel-button` visible; "rust" finds Rust from any tab.
7. **Fix ring chip hover:** keep the monogram legible (white on the black chip). Pass: the label's contrast is at least 4.5:1 in the hover state.
8. **One solid fill per viewport on phone and at load:** on phone the header "Try Hanzo" is outlined while the hero ask is on screen, and on desktop there is no 600 ms window with two black fills. Pass: at most one solid black button in every frame of the 0 to 8 s sequence at both sizes.
9. **Add Copy confirmation:** the label or icon changes for about 1.5 s after a successful copy (with the confirm sound). Pass: the button text or icon differs from rest 200 ms after the click.
10. **Tighten dead space:** cut the ~250 px blank bands between Start and Catalogue and before the black room down to the section-padding scale. Pass: no 801-px viewport while scrolling is more than 60% empty.
