## Fixes, in order
1. **Give the playground a resting state.** Prefill the request with a scripted sample built from Hanzo's own detector list (one card number, one email, one IP) so the output is already redacted with counts when it scrolls into view; typing replaces it. Fill the left column (or collapse the layout to a single centred object) so there is no 500px of blank beside it.
2. **Cut the black chip wall.** Detector chips become outlined/quiet toggles (filled ink only for the on-state tick or a small dot), so the viewport has one solid fill: the header ask.
3. **Fix reduced motion on the stage.** Under `prefers-reduced-motion` unpin and stack all six panels (as on phone or as static rows) so panels 02–06 render; no blank 3,000px.
4. **Drop the invented h2.** Remove "Each becomes a typed marker" as a heading; the playground needs no new headline (or reuse an existing Hanzo label as a caption).
5. **Make the hero console say something.** Replace the grey bars with a scripted request in words from the page (the agent prompt line or detector names) so the redaction is legible in 5 s; render the final frame in server HTML so JS-off is not an empty console.
6. **Stage 05 gets the same stage surface** as the other five, and a moment: the "content" row striking through and the "hash" row writing in.
7. **Stop wrapping in stage 02 and the marker radios.** Keep "Luhn ✓" on one line (smaller badge or move it under the tile label); let marker radios scroll or shrink their mono size at 375 so `[card numbers]` never breaks.
8. **Close the gaps.** Remove the ~230px empty band between hero and stage at desktop and the ~130px under the closing band before the footer.
9. **Small states.** "Deploy to Cloud" to a 44px target on phone; the 41px control to 44px; phone rail `scroll-snap-type: x proximity` with a 14–18% peek; band ask hover should change more than a faint fill (e.g. ink fill or arrow travel).
