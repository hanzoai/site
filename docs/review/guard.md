## The 11 answers
1. **Sells in 5 s, moves in 1 s: yes.** Black room, "Guard", one line, one ask, and a demo card that starts typing within 1 s ("C|" at 1 s). The card then redacts to `[CARD]`/`[EMAIL]`, underlines the injection, fills the confidence meter to "blocked" and streams a redacted reply, settling by about 8 s, with a pause control. This is the best thing on the page. The hero is a centred head in a big boxed card, but the box is live, not static.
2. **One in, one out: mostly.** "What it looks for" is a pinned stage (3,877 px) where 01–06 swap one panel under a gliding numbered tab rail. That is the right idea. But the swap is only the object: each chapter's heading and paragraph sit under the panel at y≈673–710 of 801, so the words you need arrive at the fold, below the thing they explain. After the stage, "Paste and ship" and "Each becomes a typed marker" go back to reading like a document, with about 300 px of dead white above and below "Paste and ship".
3. **A real object in every section: yes.** Hero demo; six stage panels (pattern list with a confidence bar, typed-marker tiles with a Luhn tick, request/reply GUARD pills, dial toggles with a token bucket, struck-out content against its hash, proxy/CLI/MCP); an agent-prompt block with Copy; a live redaction playground; a contour-line drawing in "Get Guard". Panel 03's object is thin: two cards and a toggle floating in a 370 px grey box with about 120 px of empty space above.
4. **One ask, nothing floating, scale rhythm: partly.** On desktop the header ask becomes "View on GitHub" once you scroll, which matches the hero and band. On phone it stays "Try Hanzo" all the way down, so the ask changes with screen width. Nothing from the page floats over content (the cookie card is shared). Rhythm is flat: the h2 and every chapter h3 are all 26 px (21 px on phone), and "What it looks for" sits right above "Six shapes an injection takes" at the same size, so it reads as two equal headlines. Nothing grows or shrinks as you scroll. The closing block packs a 44 px h2, a mono eyebrow and a 21 px lede into about 60 px with no air.
5. **Hover and press answer: yes.** The hero GitHub button, the 01–06 tabs (fill), Copy (inset fill) and the marker chips all answer. Tapping a chip on phone flips it from ink to outline, and the redaction updates. Press on the pause control is scale 0.97. Nothing fades, nothing jumps.
6. **Overlap, font swap, layout shift: one real fault.** CLS is 0.0003 and nothing overlaps at 1470 or 375. There is no horizontal scroll at 375 or 320; the only elements past 320 belong to the shared header. **A page hydration diff remains:** with prefers-reduced-motion, `Guard > HeroObject > motion.div` renders `style={{transform-origin:"50% 0%",transform:"none"}}` on the server and `style={{}}` on the client, so the red Issue badge appears on every reduced-motion load. The badge on my normal-motion walk came from my own pre-hydration screenshot; four clean loads without one gave 0 errors, so that one is not counted. The playground textarea shows the browser-default resize grip, which counts as a browser-default control.
7. **Reference: apple.com product page.** One idea per screen, a pinned stage where one panel changes, a numbered sub-rail. That motion is really there. The chatgpt-enterprise calm is not there in the two full-bleed sections that follow.
8. **Different from neighbours: partly.** The typing-and-redacting demo is its own signature, and the in-page playground is a strong second moment. The shell around it (black hero, centred 52 px h1, one pill, a big rounded card, then a light pinned stage) is the shared cloud-product pattern, so the first glance looks like its siblings.
9. **18 parts: mostly covered.** The page has strategy (one ask), its narrative, conversion (hero, header, band), trust (Apache-2.0, the GitHub org), content, the system, components, motion (time, scroll, state and pointer), mobile (the stage becomes stacked panels), accessibility (a pause control and reduced-motion end state) and performance. It falls short on the visual system (inconsistent gutters) and on states (the hydration diff).
10. **Banned tells: two.** (a) **Three equal boxes in a row**: panel 06 is proxy / CLI tool / MCP server as three identical white cards. (b) **Inconsistent spacing**: the pinned stage and hero sit in the ~1152 px container (left edge 159 px), while "Paste and ship" and "Each becomes a typed marker" run edge to edge on a 24 px gutter (left edge 24 px), so the left edge jumps from 159 px to 24 px between sections. No gradient text, no Inter (Zen and Zen Mono only), and no eyebrow above a headline; "PASTE YOUR OWN" and "GET STARTED WITH GUARD" sit below their h2s.
11. **Copy untouched: as far as can be seen, yes.** The words read as Hanzo's own, and no invented numbers appear.

## Fixes, in order
1. Panel 06: replace the three equal cards with something that is not three equal boxes. For example, one row with the proxy as the focus and CLI tool and MCP server as two smaller trailing items, or a single line drawing of request → Guard → {proxy, PTY, MCP}.
2. Put "Paste and ship" and "Each becomes a typed marker" back in the same container and gutter as the hero and the stage (left edge 159 px at 1470). Cut the dead white around "Paste and ship" to the standard section padding.
3. Fix the reduced-motion hydration diff in `HeroObject`: render the same `style` on server and client, and apply the reduced-motion transform only after mount (or never set transform-origin/transform under reduced motion on either side).
4. Pinned stage: move each chapter's h3, `0N / 06` and paragraph up beside or above the panel (8/5 split, heading left), so the words and the object change together inside the viewport. Trim the grey stage box so its object is not floating in empty space (panel 03 especially).
5. Give scale rhythm: either drop the separate "What it looks for" h2 to an 11–12 px mono label beside the 01–06 rail, or let the active chapter's h3 be the one size-moment. Don't stack two 26 px headings. In "Get Guard", give the eyebrow and lede proper space (golden steps 10.5 / 17 px).
6. Style the playground textarea: hide the native resize grip (`resize: none`, or a custom handle) so no browser-default control shows.
7. Make the header ask consistent: if the page's ask is "View on GitHub" on desktop, the phone header should carry the same ask, not "Try Hanzo".
8. Optional, for the first-glance difference: make the hero card less of a standard boxed card, for example by letting the redaction bleed to the gutters or reducing the frame, so /guard does not look like its cloud siblings before the typing starts.
