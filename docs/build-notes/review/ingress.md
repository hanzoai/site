Arrival comes from the lede and ask fade (`.v2-in`, the ask is still at #404040-ish at 250 ms), not from a headline cut.

The sweep shows that in every one of the 5 wipes, `--out` reaches 0 at about 150px into the wipe, but the incoming text only cuts in (`data-t=1`) at about 250px. ## Fixes (in order)
1. **Close the blank gap in every wipe** (`components/pages/cloud/Ingress.jsx` `useWipe`, `components/pages/cloud/Ingress.css` lines 62 to 74). The clip-path wipe already covers the old scene, so stop fading it out ahead of the cover: drop the `opacity: var(--out)` rule on `.ig-scene-l` and `.ig-scene-r`, or fade `--out` between kin 0.45 and 0.5, so the outgoing text holds until the incoming h3 cuts in at 0.5. Also start the incoming drawing at its first visible pixel, so the revealed slice of the card is never an empty white box. Acceptance: in a 51-step sweep, no frame has neither scene's h3 visible, and no frame shows an empty card slice.
2. **Make the h1 cut-in visible.** `Lines` on the hero h1 renders complete at 0 ms. Run the 105%-to-0 line mask (700 ms, ease-emphasis, 60 ms per line) after hydration, the way the chapter h3s do, while keeping the words in the server HTML.
3. **Flatten the chapter cards.** Remove `box-shadow` from `.ig-scene-r` (Ingress.css:59) and let the tint change between scenes carry the depth. Tiles are flat; only floating things take a shadow.
4. **Tokens for the literals** in Ingress.css (`#fff`, `#0a0a0a`, `#737373`, `rgba(...)`).
5. **Label the anonymous backend tiles on the board.** The first and third backends are only grey squares and read like a loading skeleton. If there is no Hanzo word for them, give them the same pod treatment as the "static / from disk" row (for example the pod count as a figure) so all three rows read as one designed set.
6. **Shared, request only:** the "Deploy to Cloud" link in `GetIt` needs a 44px hit area at 375 (`docs/build-notes/requests/ingress.md`), and the phone header should carry the page's ask rather than a solid "Try Hanzo" (shared `Ask`).
