## Missing from the 18 parts
- **Part 3 (phone):** the h1 is 27.75px instead of 3 lines at 40px, and the hero object does not show 80px+ of product inside 660px (the stream starts at ≈663).
- **Part 4 / 3.2 rule 6:** on phone the sticky header never carries the page's ask ("Browse 260+ tools"); it stays "Try Hanzo". It does swap on desktop.
- **Part 6 / 11:** the config captions overflow and clip at 375 and 320. The sheet 01 chip overflows at 320.
- **Part 8:** the CodeBlock Copy buttons are 32px tall on desktop (the rule is 44px).
- **Part 9:** more than one continuous mover per viewport (sheets 01 and 02 together, and four rail cards).
- **Part 16:** "the paste runs in zsh" fails. The bash block copies `hanzo mcp              # stdio; the binary downloads on first run`. In default zsh (`interactivecomments` off), `#` is not a comment and `;` ends the command, so the paste runs `the binary downloads on first run` → `command not found: the`. The copy also queues `hanzo mcp` and `hanzo mcp -t sse` back to back, and the first one blocks.
- **Part 11:** several phone screens are completely still at rest (figures, paste and domains intro, config, close). The phone is not its own composition. The sheet art stacks as tall cards instead of 3 compact panels.

## Fixes (in order)
1. **Phone caption clipping:** set `.mcp-code-c { white-space: normal; overflow-wrap: anywhere; }` inside `@media (max-width: 899px)`. Another option is to make each caption the CodeBlock's label row. Check that nothing reaches past x=375 or x=320 (`.mcp-cfg` currently clips at 596). Also wrap the `.mcp-art.a0` chips at 320 by dropping chip padding to 8px 10px under 360px.
2. **Shell block that pastes in zsh:** move the two `# …` comments out of the copied text. Show them as `user-select:none` annotations beside the lines, or as a caption under the block, keeping the words for parity. The copy then holds only `npm i -g hanzo` / `hanzo mcp` / `hanzo mcp -t sse`. Better still, give each command its own copy row so a paste never queues a blocking `hanzo mcp` before `-t sse`.
3. **Phone hero:** set the phone `.mcp-h1` to 40px (deck step) in 3 lines and tighten `.mcp-hero` top padding (h1 currently at y=164) so the stream's top 80px+ lands inside 660px. On phone, show the stream's top 4 rows (row height 40) instead of the full 10-row panel.
4. **Phone sticky ask:** file `docs/requests/mcp.md` so the shared header swaps to the page ask ("Browse 260+ tools", `data-ask` twin of `mcp.hero`) on phone the way it does at 1470. At 320 the header ask must not clip.
5. **One continuous mover per viewport:** start the `.mcp-art` cycles only for the sheet currently on top (IntersectionObserver with amount 0.6, adding a class that enables `animation`), and pause the others. On the rail, cycle chips only on the card nearest centre, or on the hovered or focused card.
6. **Domain card hover that tells you something:** on `@media (hover:hover)` hover or focus, lift the card 4px and reveal the hidden tool count ("+10") as the chip row expands to show 2 more names (transform and clip-path only), so the hover previews what the sheet will hold.
7. **Phone stillness:** give the figures a once-only mask rise per figure as each enters on phone (already built, currently fires before arrival). Start the typed terminal at 40% in view, and let one rail card's chips cycle while it is in view, so no phone screen is dead at rest.
8. **Copy buttons:** raise `.mcp-cfg .x-copy` to 44px tall on desktop (padding, not layout jump).
