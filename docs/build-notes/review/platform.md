## The 11 questions

**1. Does the first screen sell in 5 seconds, and does something move within 1 second?** Yes, mostly. "The AI-native cloud." at 84px, one lede, Start building (solid) beside Inspect the stack (outline), the docker strip with a working Copy (it copies exactly `docker run -p 8080:8080 ghcr.io/hanzoai/cloud` and says "Copied"), and a proof row. The isometric stack starts fanning its layers by about 1 s and cycles labels on its own (Gateway, AI Gateway, Zen, Agents, Inference Engine, Kernel DSL) for the whole 8 s. That is a real idle object. Two problems: on desktop the cookie card covers the proof row ("400+ callable models · GPUs ...") on first load, and on phone the art paints oversized for the first second and then jumps (proof 2).

**2. As you scroll, does one thing come in as one goes out?** Partly. The pinned black map is the right idea: one layer group at a time, the stack lifting the matching plates. The switch is out of step, though. The left list and its figure (95.6%, 3.02x) fade to about 10% before the next group arrives, while the stack has already moved on, so for about 300 px of scroll the left half is near-black. The entry into the room is a settled frame (scrollY 433) of a black screen holding only the stack, with every word at opacity 0. The six plane chapters (Compute, Data, Anywhere, Security, Ship, Pricing) do switch one at a time, but each switch is a whole-scene opacity fade with a washed-out midpoint. All six use the same layout (heading left, grey card right), so after the third it reads like a document with a fade.

**3. Does every section hold a real visual object?** Yes, and this is the page's strength: the hero stack, the 11-layer map, the directory with a live Catalog preview (contour drawing plus the description), the Compute console UI, the Data tiles, the control-plane tree, the security checklist, the Ship timeline, the Pricing meters, the semantic graph, the self-typing API explorer, the loop diagram and the open-source terminals. Gaps: the "11 native layers" proof block has about 130 px of empty white under it before the Band. With JS off, the four Data tiles (Datastore, Object Storage, Base, Memory) and 32 other elements stay at opacity 0, so that chapter loses its object.

**4. One ask in the sticky header, nothing floating, scale rhythm?** Desktop handles it well. The header ask is outlined while the hero's Start building is on screen, then becomes "Start building" solid. On phone (375 and 320) the header keeps a solid black "Try Hanzo" next to the solid black "Start building" in the first screen: two solid fills with two different labels for one action (shared header plus page). At the Band, the header's solid "Start building" sits above the Band's white "Start building", again two fills in one viewport. Nothing floats over content except the shared cookie card, which on desktop covers the hero proof row and half the ZAP bar. Scale: h1 84, "One stack" 44, chapter heads 32, section heads 26, figures large, captions 12-13. There is rhythm, but the Band h2 is 88px, which is off the 84/112 scale and makes the page big at both ends.

The header ask's hover drops **opacity to 0.88** as well as changing fill, a fade on hover (shared chrome). Directory hover fills overshoot their column rule by about 8 px.

**6. Overlaps, font swap or layout shift?** No font swap seen, CLS under 0.005, and no overflow at 320. Overlap: the cookie card sits on the hero proof row and the ZAP interconnect bar at 1470 (shared chrome). **7. Which reference does it feel like, and is its motion there?** apple.com's pinned scrubbed scene, in the black map, and that motion is really there: the stack lifts and parts with the scroll.
