# Requests from /telemetry (7 Nov)

- **components/Shell.jsx `FooterHTML` (shared footer): hydration mismatch.** The 7 Nov critic saw Next's red "1 Issue" badge ("A tree hydrated but some attributes of the server rendered HTML didn't match") on 3 of 4 fresh loads of /telemetry and 4 of 4 of /tunnel, pointing at the footer. `FooterHTML` renders the live footer as a `dangerouslySetInnerHTML` string, so React compares every attribute inside it. Likely causes, in order: (1) the footer's "Ask Hanzo anything" input is touched before hydration (an extension, autofill, or a test tool's screenshot adding `style=""` / caret styles to inputs), and any such attribute on the server string's elements counts as a mismatch; (2) a chrome script (`Chrome.jsx`, `HeaderTools.jsx`, `Ask.jsx`) writes `data-*` attributes into the injected markup before React hydrates it. Asked for: add `suppressHydrationWarning` on the two shell wrappers, or mount the footer markup after hydration (render an empty wrapper on the server pass, fill it in an effect), so a touched input never raises the badge on every page.
- **components/Ask.jsx (phone ask bar):** on phones the header keeps Hanzo's solid "Try Hanzo", so a page whose own ask differs ("View on GitHub") shows two solids on its first screen unless the page outlines its own button. /telemetry outlines its "View on GitHub" at ≤700px. Asked for: on phones, the header's button goes quiet while the page's own ask is on screen, as it already does on desktop.
