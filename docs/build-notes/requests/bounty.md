# /bounty: requests to the shared system

- **Ask.jsx (desktop header ask can revert mid-page).** The desktop effect writes the page's ask into the header's button once and caches `shown`; it only rewrites when `shown` flips. If the header's text node is put back to "Try Hanzo" underneath it (a header re-render, e.g. Fast Refresh while other files change in dev), the cache still says shown and the header reads "Try Hanzo" until the hero comes back. The 7 Nov 16:30 review saw this on slow walks. In 4 slow walks here (120 and 200px notches, 1s dwell) it did not reproduce once the page guard was in. Suggested fix: in `update()`, compare `btn.textContent` with the wanted label each time rather than only on a `shown` change. Page-local workaround: `useHoldHeaderAsk()` in `components/pages/Bounty.jsx` re-asserts the words, link and `data-cta="header-ask"` while the hero's ask is above the header (desktop only).
