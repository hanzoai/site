What a bot is

A teammate with its own computer

Not a chat window. A bot has a computer of its own and works while you do something else.

01

Its own computer

Each bot runs in its own sandbox with a browser, a terminal and your apps. Nothing it does touches your machine unless you let it.

02

Works where you work

Sign it in once. It uses the same tools and websites you do, including the ones that are hard to automate.

03

Comes back when it is done

Give it a task and go do something else. It returns with finished work and asks only when it needs your say.

Work with many at once

Bots that hand work to each other

One gateway, many bots

Each bot has its own workspace, sign-ins and history, and each message goes to the bot it is meant for.

Sub-agents

A bot can start background runs that work in parallel and post what they found back in the chat that asked.

Bots message bots

One bot can read another’s session and send it a message, so a handoff needs no copy and paste.

How multi-agent works

Show it how it is done

Teach it a routine once

Skills

Write the steps in a plain Markdown skill, and the bot uses it whenever the job comes up.

On a schedule

Every morning, or in twenty minutes. Scheduled jobs survive a restart and can post the result to a chat.

Your say at each step

A multi-step routine can stop at the steps you mark and wait for your yes before it goes on.

Skills in the docs

Gets better as it goes

It remembers what it learns

Memory is files

Decisions, preferences and running notes go into Markdown files in its workspace, not into the model.

It looks things up

It searches those notes when it needs them, so what you told it last week still counts.

Yours to read and fix

Open the files, correct them or delete them. The next session starts from what you left.

Agent Architecture & Pricing Model

Why Hanzo Bot is built and priced this way

Designed around the real economics of autonomous resident agents: dedicated sandboxes, cost-efficient model tiering, and transparent, auditable memory.

Compute Floor

Why a $100/mo entry floor?

Not a chat window. A resident cloud computer.Standard chat models terminate compute as soon as tokens finish streaming. A resident Hanzo Bot lives in an active cloud sandbox with its own Chromium browser, bash terminal, isolated filesystem, and scheduled cron jobs. The $100/month floor covers continuous cloud sandboxing and dedicated container resources.
Token Economics

Routine work at 1/5th the token cost

Intelligent routing through Enso & Sol 6.1.Up to 90% of a resident bot’s daily work consists of triaging inboxes, summarizing documents, parsing receipts, and scraping pages. Rather than burning expensive frontier reasoning on routine tasks, Hanzo Bot executes routine loops on Enso & Sol 6.1 at ~1/5th the token price, leaving your monthly AI allowance intact for the tasks that need it.
Frontier Autonomy

Zen Ultra for complex reasoning ($800/mo)

Extended capacity for non-stop autonomous loops.When your bot needs to perform deep multi-hour research, autonomous software engineering, or multi-step strategic analysis, the Ultra tier ($800/mo) includes Zen Ultra and Astra Ultra frontier models with unlimited capacity, no hourly rate caps, continuous execution as long as you have funds, and an automatic 20% discount on all usage exceeding $800.
Auditable Memory

Plain Markdown files you can inspect & edit

No black-box fine-tuning or opaque vector locks.Hanzo Bot records what it learns in human-readable Markdown files in its workspace (`MEMORY.md`, `SKILLS.md`). You can open them, audit them, version-control them in Git, or delete them anytime. The bot begins every session from what you leave.

FAQ

Questions

What is Hanzo Bot?
An AI teammate. It runs behind a gateway on your machine, in our cloud, or both. You message it on the chat apps you already use, and it does the work with its own browser, terminal and tools.
Is it open source?
Yes, MIT licensed, at github.com/hanzoai/bot. Run it on your own machine and your keys and data stay there.
What does it run on?
macOS or Linux, and Windows through WSL2, with Node 22 or newer. A Mac is only needed for macOS-only tools; a small server works for everything else.
Which models does it use?
The ones you choose: API keys for the providers you use, or a local model so your data stays on your device. hanzo-bot models manages the choice and the sign-in.
Can it work on a schedule?
Yes. Cron jobs run it every morning or at a set time, survive a restart, and can post the result to a chat.
Does it remember what I tell it?
It writes what it learns to Markdown files in its workspace and searches them when it needs them. If you want something to stick, ask it to write it down.
I use OpenClaw. Can I move over?
hanzo-bot migrate openclaw shows what would move and writes nothing. Add --apply to move config, credentials, workspace, sessions, skills and cron jobs. It never changes ~/.openclaw.
What does Hanzo Bot cost?
Running Hanzo Bot on your own machine is 100% free and open source (MIT licensed). In our cloud, resident bots come with the plans listed under Pricing, each with the number of bots it states — compute is metered per bot-hour beyond the included allowance, with auto-reload to keep going.
Why is there a $15/mo floor for cloud resident bots?
Unlike simple chat prompts where compute ends as soon as generation stops, a resident bot has an always-on dedicated cloud environment. It runs an isolated sandbox container, headless browser, terminal, filesystem, and active cron listeners. The $15/mo floor covers dedicated compute and guarantees uptime.
How do model token costs work for bots?
Routine tasks (sorting inboxes, web scraping, scheduling, receipt parsing) execute on fast, cost-effective Enso and Sol 6.1 models at ~1/5th the token cost of frontier models, preserving 85-90% of your plan allowance. Higher tiers include Zen Ultra and Astra Ultra frontier models for complex multi-step reasoning.
